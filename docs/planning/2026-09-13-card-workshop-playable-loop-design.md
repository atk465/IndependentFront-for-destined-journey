# 卡牌工坊 真机可玩闭环 —— 访谈共识总览（设计真源）

- 日期：2026-09-13
- 分支：`card-workshop-mvp`
- 性质：**27 问深度访谈的裁定汇总**，本轮实现（会话层装配等）的设计依据
- 前序：五阶段引擎工作（阶段 1 收尾 / 2 启封 / 3 战力+制卡桥 / 4 地景 / 5 战斗内接线）已全部合入本分支

## 0. 根裁定

**完成标准 = 真机可玩闭环**：玩家在真实战斗里能从自己卡组打出卡、看到启封判定、看到召唤/地景/禁忌生效。委托/内容/数值分支依此排序（战斗闭环优先）。

## 1. 分支 1：战斗中玩卡的会话层装配

| #    | 决策       | 裁定                                                                                                                                                                                              |
| ---- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1.1  | 入口       | **自由文本为主、双通道装配**：`player-input.ts` 确定性解析器优先（结构化路径，零 AI）；战斗主持人 AI 提名兜底（翻译层装配）。共享唯一解析器「卡名 → 背包真实 CardItem → `payload.card`」（铁律②） |
| 1.2  | 卡的集合   | **编组制**：只认 `cardAlbum.deck` ∩ 背包实物，开战时会话层拼名单快照进战斗上下文，战斗期间固定。名字在 deck 但实物丢失 → 不可打出、明确提示                                                       |
| 1.3  | 消耗规则   | **按卡类型区分**：技能/领域/场景/物资 = 消耗（settlement 统一结算，**哑火不耗**——封印破裂才耗）；装备/召唤/军团 = 永久。素材卡不可战斗打出                                                        |
| 1.3a | 类型系统   | **形态词条制**：词条含「地景/装备/技能/领域/召唤/军团/物资/素材」八类之一即该类型（参考路线 A 卡包截图），皆无 = 技能卡（缺省）。多形态词条按固定优先级取首个。「禁忌」是稀有类横切标记，非第五类 |
| 1.3b | 永久卡语义 | **每打必判 + 在场绑定**：每次打出都按背包 sealed 状态过启封判定（战斗内外零回写）；装备光环期间/伙伴在场期间不可重打（明确拒绝），哑火后可再试                                                    |
| 1.4  | 战斗 UI    | **只读卡组条 + 四态显示**（可用/生效中/伙伴在场/本局已耗，即会话临时账的可视化）+ **点击填输入框**（仍走文本通道，不开第二条命令直发路径）                                                        |

## 2. 分支 3：契约召唤（伙伴系统）

| #      | 决策       | 裁定                                                                                                                                                                                                                 |
| ------ | ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 3-根   | 契约制     | **C' 制**：伙伴是世界内永久的契约存在；**损伤由卡片承载，伙伴本体永远安全**                                                                                                                                          |
| 3-①a   | 损坏触发   | **一击损坏制**：伙伴战斗内被打倒（HP 归零退场）→ 卡进入损坏状态；平时伤害是战术性的（本局有效战后消散），只有击倒穿透到卡。启封判定失败**不损坏**卡                                                                  |
| 3-①b   | 修复双轨制 | **模板素材直修必成功**（配方按品质档，制卡台加「修复」模式）+ **额外素材强化**（修复同时强化，永不阻断修复）。修复是恢复性作业，无检定失败                                                                           |
| 3-①c   | 强化词条制 | 额外素材 → 融合内核确定性推导 → **加词条**（改卡不改兽）。修复不加形态词条（类型出厂定死）                                                                                                                           |
| 3-①d   | 品质跃迁   | 素材品质 **高于** 卡品质 → 升一档 + 词条 + 属性强化包。三细则：一次最多 +1 档（溢出浪费）；卡 `cardTier`（战斗真源）与角色 tier（世界内投影）**同一次提交双写**；词条槽 = f(品质)（白铁2…星辉6，槽满只强化不加词条） |
| 3-②    | 契约映射   | **名字即契约**：伙伴角色名 = 卡名；契约存在性 = 角色列表存在同名角色。首召 CharGenRequest 生成（约束名=卡名）入库；再召按名 `templateRef` 实例化。叙事删除角色 = 契约自愈解除、卡回未契约态                          |
| 3-规模 | 伙伴规模   | 自然上限（= 召唤卡种类数 ≤ 卡组 12），不设硬限；多周目随存档隔离                                                                                                                                                     |

## 3. 分支 2：委托系统

| #      | 决策     | 裁定                                                                                                                                                                                                                      |
| ------ | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2.1    | 模板载体 | **内容包第 15 分节**（纯 JSON：名称/描述/`requireCard` 过滤器/奖励包/`minReputation`），照 ADR-32 随机事件完整先例（`{{COMMISSIONS}}` 单通道注入、坏定义跳过、随包换）。接取实例化为既有 quest（模板/实例分离，零新实体） |
| 2.2    | 验收     | **组合过滤器制** `matchesCommission(card, req)` 纯函数：`minTier` + `formEntry` + `elements` + `exactName` 全可选全组合、全命中合格                                                                                       |
| 2.2-续 | 交付     | **上交制**：卡移除与奖励（GC/素材/声望）同一次原子提交——防刷是结构性的。**已契约召唤卡可自由交付**（卡消失=契约解除、伙伴角色留存，UI 警告不硬禁）                                                                        |
| 2.3    | 声望     | **`SaveProfile.reputation` 单一数值**（FP 先例同构：`delta_variable` 白名单加条目、AI 零写路径、stat-projection 只读投影）。委托模板带 `minReputation` 解锁门槛                                                           |

## 4. 分支 4：内容与数值体系

| #        | 决策         | 裁定                                                                                                                                                                                                                                                        |
| -------- | ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 4-①      | 形态词条来源 | **炼制提名制**：`<craft_request>` 参数增 `formEntry` → normalize 白名单校验（八类）→ 制卡桥并进词条。与 `CraftIndustry` 同构。**修复强化不加形态词条**                                                                                                      |
| 4-素材卡 | 素材卡定位   | **万物封卡**：运输形态（尸体→素材卡，叙事侧走既有 craft/item 链提名 `formEntry=素材` 产出）、委托奖励载体、交易通货、本身可炼制（带词条素材卡，如「燃爆的海怪眼睛」）；与裸材料在炼制/修复中等价（都是 InventoryItem，`toMaterial` 天然兼容）。不可战斗打出 |
| 4-②      | 词条战斗语义 | **双源制**：automata 为战斗真源——AI 炼卡经 item_gen `<automaton>` 透传 `CardItem.automata`（制卡桥加透传）；强化词条查**内置编译表**（词条 → automata 模板 + 属性加成），未知词条安全无效果                                                                 |
| 4-RPG    | 数值体系     | **接入引擎既有 RPG 数值体系**（tier/level/五维/HP/MP/SP），卡面不另设 ATK/DEF。词条属性加成走**战斗内 modifier**（卡=装备隐喻，StaticModifier/collect_mods 既有）；世界内持久成长只来自品质跃迁属性包                                                       |
| 4-天赋   | 天赋系统     | **后置扩展 + 口径预钉**：只有**玩家主角**有天赋（伙伴无）；挂 `CharacterState` 可选字段（零迁移，`cardAlbum?` 先例）；效果走与词条同源的 modifier/automata 机制。实现时点 = 闭环真机验证后（存量伙伴无天赋为既定语义，新内容不返工）                        |
| 4-内容   | 内容边界     | 三条：①相生相克表冻结现有 8 对（扩展待内容仓/主人定表）；②禁忌卡不做预置清单（词条标记 + 深覆写走既有 Adjudicate）；③战利品封卡走既有侧链无新入口。**机制先行、内容自然生长**                                                                               |

## 5. 分支 5：数值流程

**本喵起草 + 既有尺度校准 + 主人终审**：按根 AGENTS.md 公开摘录的世界书核心数值表（T1-T7 梯度）+ 引擎既有阶梯逻辑（DC 8→20 等已定表口径）起草全部待填表（修复配方/跃迁属性包/词条编译表/委托奖励/喂养经济），汇总「数值总表」文档，每格标推导口径，主人逐表终审，真机走查后调参。

## 6. 分支 6：验证与交付

- **分层走查**：第一层本喵无 LLM 自动走查（dev server + 浏览器自动化：卡册/制台/编组/卡组条四态/确定性链路）+ 全量单测保底；第二层需 LLM API（炼卡全流程/真实战斗/委托演绎，环境可用则自动跑）；主人终验「好不好玩」。
- **交付目标 = 方案一**：走查过 → push `card-workshop-mvp` 到 **origin（atk465 fork，主人自己的仓库）** → 盯 GitHub Actions CI 至绿。**无 upstream PR 环节**（主人裁定 PR 到自己仓库 = 直接 push）。
- **安全收尾**：确认不再 push 后 revoke `.git/config` 内嵌 OAuth token（档案 §7）。

## 7. 实现范围与顺序（本轮开发清单）

1. **卡类型系统**：`card-workshop/card-kind.ts`（八类形态词条判据 + `isConsumable`，扩展现有 landscape.ts）
2. **会话层装配**：玩卡解析器（卡名→CardItem→`payload.card`，编组快照闸门）接入 player-input 与 coordinator 翻译层
3. **会话临时账**：已打出消耗卡 / 在场光环与伙伴绑定（重打拒绝依据）+ settlement 消耗结算
4. **修复系统**：配方表结构 + 制卡台修复模式 + 品质跃迁双写
5. **契约召唤接线**：首召入库（名=卡名）→ 召唤池运行时来源 → 再召 templateRef
6. **委托基建**：第 15 分节 schema + `{{COMMISSIONS}}` 注入 + 验收过滤器 + 上交/声望结算
7. **战斗卡组条 UI**：四态显示 + 点击填输入框
8. **数值总表**：全部待填表起草 + 推导口径，交主人终审
9. 每步独立提交、`npm run gates` 全绿；走查 → push → CI → revoke
