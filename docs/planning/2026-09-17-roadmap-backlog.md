### 已确认需要「跨战斗账本」的三条 SS（建议一次做）

一拳超人系统 / 败犬烙印 / 好运之骰 都需要一个**跨战斗的持久账本**，
建在 `SaveProfile` 上（先例：`narrativeIntents`、情绪素材的 `lastExtractDay`）。

| 天赋 | 需要账本记什么 | 还需要什么 |
| ---- | -------------- | ---------- |
| 一拳超人系统 | 今日是否已出拳（gameDay） | 出拳后 24h 虚弱——状态效果落地 |
| 败犬烙印 | 烙印累计数（战败 +1） | 制卡时消耗一枚扭转一次词条冲突（接 craft 流程） |
| 好运之骰 | 今日是否已投骰（gameDay） | 十面骰十个结果各自的兑现方式（**待主人定**） |

**设计决策待定**：好运之骰的十个结果里，「提升一级」「刀刀暴击」等各自要接
不同的系统（升级/战斗暴击/素材掉落），需要先定哪些走 Code、哪些走叙事。

### 已裁定：好运之骰的十面兑现口径（2026-09-17）

**裁定**：十面 = 十条数据，每面自带兑现口径，**全部 Code 兑现**，AI 只负责把它
写成一段像命运的话。理由：抽奖是本作唯一的纯随机入口，玩家会反复投，结果必须
可复算、可审计，不能靠叙事手感。

| 点 | 面 | 吉凶 | 兑现 |
| -- | -- | ---- | ---- |
| 1 | 杂鱼杂鱼 | 凶 | 金钱 −50（clamp ≥0） |
| 2 | 谢谢惠顾 | 平 | 无 |
| 3 | 再来一次 | 吉 | **退还今日次数**（不写账本） |
| 4 | 福缘天降 | 吉 | 金钱 +150 |
| 5 | 制卡顺利 | 吉 | 当日制卡评级上浮一档（大失败→失败→成功→精益求精） |
| 6 | 红鸾天喜 | 吉 | 好感最高的那位 +5 |
| 7 | 材料秘境 | 吉 | 稀有素材 ×3（与拆解同一命名口径） |
| 8 | 刀刀暴击 | 吉 | 当日战斗行动值 ×1.25 |
| 9 | 提升一级 | 大吉 | 等级 +1 |
| 10 | 屠龙宝刀 | 大吉 | 星辉档卡牌一张（复用祭坛抽卡内核） |

点数越大越好（玩家一眼能读）。5/8 两面是**当日增益**，走
`worldFlags.dailyBuffs.<key> = gameDay`，跨天自动失效。
本条落地后，`日掷` 这个条目种类可被 S「命运之骰」（六面）直接复用——
只需补一张六面表并给该种类加 `faces` 档位。

### 已落地：新管道首批三条（2026-09-17）

- **抽奖内核（`material-gacha.ts`）**：素材十连——`times` 发按权重滚稀有度，
  **保底不靠「最后一发必出」而是抽完补齐**（把最差的一发抬到保底档，前面抽得
  好也不吃亏），突变面 3% 出带高阶突变词条的素材。保底档由等级经
  `tierForLevel` → `TIER_TO_RARITY` 换算（与拆解/转化同源，不另起等级口径）。
  顺带把 `TIER_TO_RARITY` 的两份副本合成一份（原在 card-dismantle 与
  companion-capture 各有一份）。
- **免死 / 复活（两条通道，分工不同）**：
  - `免死`（绞刑架幸存者）= **战中**：HP 会被打到 0 时锁血到 `hpFloor` 续战，
    每场一次（会话级守卫，与 `nukeUsed` 同款）；`mpRefill` 决定是否补满 MP。
  - `复生`（再生）= **战后**：败北结算时把 HP 抬到 `hpFloor`——不死之身，只是输了。
- **自身战斗状态（`self-status.ts`）**：玩家侧被动，开战即生效整场。
  状态名 → 机械形态走表：`隐身` → `threatDown`（并进威压同一个百分比一起缩放敌方
  意图）；`吸魔` → `regen`（新增拍内效果类型，每拍末回 HP、封顶上限）。
  认不出的状态名不进列表——不给引擎看不懂的状态占位。
  `startSkirmish` 新增 `initialEffects`，让开战就带在场效果成为可能。

**未做：亲吻女神系统**——奖励品质要按「对方实力 × 颜值 × 好感」算，其中**颜值
引擎里没有数值**（`appearance` 只是一段文本描述）。硬做只能退化成「实力 × 好感」，
那就不是描述里那个天赋。等颜值有落点（例如角色卡加一个数值字段）再说。

### 已落地：新管道第二批五条（2026-09-17）

- **战斗规则改写**（`battle-rules.ts`，三条共用一处）：
  - `惰性`（懒惰天才）：产出的生物卡带「懒惰」印记，拍内按档位概率摸鱼跳过行动、
    否则行动值翻倍。印记是**词条**（卡的单一真源），`resolveLazyCard` 纯函数收骰值。
  - `决斗`（西部决斗礼仪）：宣战后本场禁用伙伴卡（召唤/军团不上场），
    并抑制 `dot` 与 `regen`（「免疫一切外部伤害与治疗」落地为场地不在场）。
    会话加 `duel` 规则字段，拍内核按规则抑制，`startSkirmish` 也收 `duel`。
- **身后灵**（`behind-spirits.ts`，瓦尔哈拉的门票）：伙伴卡退场 → 永久守护，
  每枚按 `成灵{guardPerSpirit}` 加防御。
  **裁断**：引擎里伙伴卡不会在战斗中战死（卡没有生命值、也没有战死结算通道），
  所以把触发权交回玩家（制卡台「送她成灵」），语义仍是「她的灵魂跟着你」。
- **献祭召唤**（召唤媒介系统）：献祭当前 HP 的一部分，召唤物以「带持续拍数的 buff」
  形式落成在场效果——**没有引入新机制**，直接复用拍内的 buff 生命周期。
  「不受完全控制」由叙事承担（机械部分是纯收益，代价是即时付出的 HP）。
- **双生羁绊**（`battle-rules.ts` 的羁绊段）：制卡台指定两张伙伴卡结缘，
  两张都打上「双生」词条；**先后打出**即触发组合技（每对每场一次，
  由会话的 `comboFired` 账去重）。「共享感官」落地为「一个动另一个就应」。

### 已落地：新管道第三批三条（2026-09-17）

- **赌徒谬论**（`craft-flow-hooks.ts`）：对冲融合（相克）大失败 → 叠一层厄运
  （累计计数，不随天失效）；下一次对冲融合按层数把评级往上抬，**用掉即清空**。
  只在相克流派兑现——相克与否读产物卡的 `recipe.fusionKind`（融合内核算好的）。
- **时间回溯**：预付开关 + 失败时重裁一次（评级上浮一档），代价是精神力；
  **成功不触发也不扣**。⚠️ 描述里的「素材和状态返回制卡前」落不了地——
  见下方「制卡不扣素材」，那半边等制卡真的消耗素材时再补。
- **调教大师系统**：调教度存卡的 `data.调教`，每级 +1 卡面战力（走既有
  `cardPowerBonus`，不新开成长轴），方向（忠犬/女王）在第一次调教时定下。
  **顺手去重**：目录里这条本来有两份一模一样的（全目录唯一一处重名）。

**一条结构性观察**：这三条最终都落在「把评级往上抬」上，因为**评级是制卡唯一的
成败信号**。这不是偷懒——引擎不做 Code 侧掷骰（`rollCraftRating` 没有生产调用方），
成败由 craft_gen 声明，所以「提高成功率」在现有架构里只能这么表达。
若日后要让制卡成功率真正可算，得先让 Code 接管评级骰。

### 已落地：新管道第四批五条（2026-09-17）

- **条件经验**（`conditional-exp.ts`）：
  - `宿敌`（宿敌认证系统）：**败给更强的敌人** → 他被记为宿敌；与宿敌战斗经验翻倍，
    战胜宿敌夺取气运（一次性）并清空——一段有始有终的恩怨。
  - `打脸`（打脸升级系统）：被嘲讽标记**当天**打赢 → 海量经验 + 打脸点数；

    隔夜作废——与「环境由领域卡建立」同一个思路：把叙事事实落成可判定的标记。
- **伙伴+素材炼金**（`partner-alchemy.ts`，足之炼金术）：伙伴卡踩踏素材 → 炼出道具卡。
  产物形态由**素材类别**决定（矿→金属锭、草→药剂…），档位取伙伴与素材里较高者。
  **素材被消耗、伙伴不消耗**——这是这条天赋的真实成本。
- **主动精神冲击**（`true-name.ts`，真名看破系统）：每场一次「念出真名」，
  威力 = 基础 + 每级 × 玩家等级，**刻意不走敌方 HP 百分比**（那是「倒也可斩」的口径，
  两条大招因此各有适用面）。念过的名字会被记住，再战加成——「洞悉真名」不会忘。
- **载具部件热插拔**（`battle-rules.ts` 模块化段，模块化天才）：产出的装备/载具卡
  带「模块化」印记与改装槽；战斗中可**热插拔**一次——把已上场的在场效果换一种形态
  （助战 ↔ 灼烧）再发动。次数由条目 `模块化{swaps}` 限。

### 已落地：制卡主路（第三档改造，2026-09-17）

**动因**：制卡的消耗原先由「AI 有没有调 `craft_settle` 工具」决定——
`tool_choice: 'auto'` 下漏调就一分素材不扣，且链里的 fallback 分支还会拿
AI 写在 `<craft_params>` 里的数发 exp/fp（Agentic 失败回退 `client.chat`
**无工具**时，那个数只能由 AI 编）。

**改造**：卡牌制作不再走 AI 工具结算，改走 **Code 侧一次算完**：

| 环节 | 谁定 |
| ---- | ---- |
| 档位 / 词条 / 造价 | 融合内核（`fuse`，本来就在 Code） |
| 评级 | `rollCraftRating` + Code 侧掷骰（骰值由调用方传入） |
| 评级上浮 | 制卡顺利 +1 / 败犬烙印 +2 / 相克厄运 / 时间回溯，按序施加 |
| 素材消耗 | `consumedByRating`（成功全耗／失败保主材／大失败全耗） |
| 经验 | `CRAFT_EXP_BY_TIER × CRAFT_RATING_MULT` |
| **卡名 + 过程叙事** | **AI（无工具，只写这两样）** |

- 引擎：`card-workshop/card-craft-plan.ts`（纯函数，唯一数值真源）
- 叙事：`card-craft-narrate.ts`（内联 system prompt，无工具；提示词明令「不得引入
  或更改任何数字」；AI 不可用时用不含数字的兜底文案，**制卡不因 AI 失败而失败**）
- UI：制卡台新增「制卡」区——**玩家亲手选素材（主 + 两副）、亲手写下想做成什么样**，
  预览就显示 Code 算好的档位/词条/造价/消耗；提交时掷骰。
- 接线：`store.craftCard`（Code 算完 → 请 AI 命名 → 一次成型落库），
  叙事走 `setCraftNarrateImpl` 注入缝（与重铸同款，store 不碰 endpoint 装配）。

**同批的收口**：`craft_gen` 链的 fallback 奖励**已砍掉**（不是改成「结算才发」——
那会双发，因为结算路径的奖励本来就在 `craft_settle` 的补丁里）。现在：
结算过 → 奖励在结算补丁里；没结算 → 一分不发 + 叙事标注「未经结算」。

**顺带**：`applyCraftEntryTalents` 抽成共用函数（模块化/惰性/产出数量/战技附加），
制卡主路与 `craft_gen` 链**共用同一份实现**，加成口径不会漂。

### 制卡不扣素材（已由第三档改造解决）

**订正**：此前记的「制卡不扣素材」不准确——准确说法是「**只在 AI 调了
`craft_settle` 时才扣**」。消耗的机制（损耗率/资源成本）一直在 `craft-resolver`
里由 Code 算，`state-manager` 也会在库存不足时抛错；问题在「走不走这条路」由 AI 决定。

第三档改造后卡牌制作改走 `card-craft-plan`，消耗由 `consumedByRating` 决定，
**不再依赖 AI 的自觉**。仍有待补的两件：

- **时间回溯的「素材返回制卡前」**：现在有对象了（主路会消耗素材），
  但回溯发生在评级之后、消耗已定——要真正「返回」需要把消耗挪到回溯裁定之后。
- **素材数量语义**：一次制卡每件素材各消耗 1 份，与素材的 `quantity` 无关；
  若日后素材有堆叠经济，这里要改成按等级加权。

### 「引擎缺量」清单（做不了不是缺管道，是缺那个量）

有些天赋的描述引用了一个**引擎里根本不存在的数据**。硬做只能退化成别的东西，
那不是实现，是把天赋改坏。以下逐条列出缺的是什么量、以及补上它需要什么：

| 天赋 | 描述依赖的量 | 现状 | 补上要什么 |
| ---- | ------------ | ---- | ---------- |
